## Fix Made

`accountClient()` previously cached a rejected initialization promise after a temporary configuration/network failure. A second Sign In click on the same page repeated that old failure without retrying the connection. The failure now clears the cached initialization; successful initialization still shares one client. A browser regression demonstrates an initial 503 followed by a fresh configuration request and a normal authentication response.

The profile page now explicitly explains whether it is browser-only or saved privately across devices, and which Save button to press. No new profile fields, schema, staff permissions or paid services were added.

## Online Test Safety and Reproduction

`test_profile_cloud.mjs` is opt-in: it requires ignored configuration and the two existing `gradapp-coursework-[ab]@example.invalid` credentials marked fictional. It starts a local preview connected to the established Pilot project, signs in through the actual UI, saves distinct fictional profiles, then verifies fresh-browser retrieval and API denial paths. It does not create users, send emails or reset credentials.

Original fictional plan contents are backed up outside Git before mutation and restored in `finally`. Cleanup preserves the schema-version-2 marker required by the existing downgrade guard. An initial harness cleanup needed this correction; the final run restored and verified both fixtures. Raw credentials, sessions, browser traces, backups and student records are never committed or added to the hosted build.

Run with `GRADAPP_CONFIG_FILE` and `GRADAPP_TEST_ACCOUNTS` pointing to ignored operator-owned files, then `node scripts/test_profile_cloud.mjs`. The older `test_catalog_cloud.mjs` remains the opt-in expanded-catalog/stale-write check. Do not run either against real student accounts.

## What “Profile Storage” Currently Means

Online accounts already use Supabase Auth for identity and an account-owned `public.student_program_plans` row for their planning profile and saved programs. The profile currently contains **name, college/university and mathematical interests**; the account email is held by Auth. Saving sends the normalized plan to Supabase and reads it back after a later sign-in. RLS is enabled, with `auth.uid() = user_id` ownership policies and column grants that prevent clients changing the owner or server revision.

Local Preview uses browser storage and is deliberately not a server backup. It does not synchronize to other devices or automatically migrate into an online account. PDFs, transcripts, applications, recommendation letters and faculty reviews are outside this student site's scope.
